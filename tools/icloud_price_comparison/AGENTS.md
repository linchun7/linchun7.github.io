# iCloud+ 全球价格比较：后续修改规则

本文件适用于 `tools/icloud_price_comparison/` 及其子目录。后续维护、自动化修改和人工审查都必须遵守。

## 1. 公开仓库中的 Markdown

公开仓库只保留长期、准确、对用户或维护者确有用途的文档。当前允许的 Markdown 文件是：

- `AGENTS.md`：本维护规则。
- `README.md`：项目功能、数据和开发说明。
- `OPERATIONS.md`：长期有效的生产运维手册。
- `THIRD_PARTY_NOTICES.md`：第三方软件与许可声明。
- `data/apple-snapshots/README.md`：Apple 规范化快照格式和证据说明。

新增 `.md` 文件前，必须能证明它属于以下至少一类，并且内容会被长期维护：用户说明、运行/运维说明、公共数据格式说明、贡献规则、第三方许可。不能满足时不得提交。

以下内容不得进入公开仓库：一次性发布清单、终验/审计报告、内部签字、临时状态快照、聊天交接、TODO 草稿、截图说明、测试输出、故障取证、法律内部意见、凭据或 Token。需要本地留存时放入已忽略的 `tools/icloud_price_comparison/artifacts/`；不得使用 `git add -f` 绕过忽略规则。

修改或删除文档时必须同步清理 README、OPERATIONS、workflow 和代码中的链接/引用。提交前检查本项目全部受跟踪 Markdown，确认没有无关、过期、重复或敏感内容。

## 2. Apple 抓取与发布门禁

- 第一次 Apple 页面抓取必须完整成功，并由 `document-order` 与 `apple-markers` 两条解析路径逐字段交叉核对；单解析器结果不得发布。
- 普通价格、币种、分区或发布日期变化本身不要求第二次网络抓取；只有地区集合或容量集合发生新增/移除时，才触发独立确认。
- 结构变化的确认抓取必须禁用缓存，在共享网络预算内重试，并再次得到完整、`cross-checked` 的结果。两次成功结果的发布日期、规范化内容 hash 和结构变化集合必须完全一致。
- 第二次确认因超时、连接重置、临时 HTTP/CDN 故障等未取得完整结果时，归类为 `APPLE_CONFIRMATION_UNAVAILABLE`（暂时不可确认），而不是“内容不一致”。本次不得发布未经确认的结构变化，必须保留上一份稳定数据，并由下一次自动或人工运行重新尝试。
- 两次抓取都成功但结果不同，属于上游内容不稳定或完整性异常，必须失败关闭；不得把它降级成网络警告。
- 不得伪造第二份结果、复用第一次响应冒充独立确认、部分合并新旧地区/容量，或通过关闭测试绕过门禁。

该策略有意优先避免错误删除地区/容量。网络抖动可以延迟一次结构更新，但不能造成错误结构进入生产；普通价格更新不会承担这项额外确认成本。
