# 中英文加空格工具

## 实际处理路径

页面保留原文，将结果写入单独的只读文本框。“复制结果”只复制排版结果。
编辑原文、清空或取消会使旧结果失效。排版在可终止的 Web Worker 中完成：

页面 → worker.js → 官方 Pangu.js `spaceText` → format.js URL 保护/恢复。

普通文本的间距、标点和简单单反引号行为交给 Pangu。没有自有中英文排版规则，也没有复制或修改 Pangu 内部正则。
当前本地包为 npm pangu 10.4.1 的官方 browser UMD；只附加版本来源头，不添加旧 API 别名。

例子（当前固定版本）：

- `中文ABC` → `中文 ABC`
- `中文:ABC` → `中文：ABC`
- `中文,标点!测试?` → `中文, 标点! 测试?`
- `王·小明` → `王・小明`

这次恢复会调整部分原有字符或空格，不能再理解为“只插入空格”。
原文不会被结果覆盖。浏览器 textarea 自身会将 CR/CRLF 规范为 LF。

## 输入与 URL 范围

- 面向普通文本。单次最多接受 200,000 个 UTF-16 代码单元（界面简称“20 万字符”）；超出只拒绝处理并提示，不截断原文。
- 单次任务超过 4 秒就终止 Worker，保留原文并提示分段重试。可以手动取消；新输入和清空会终止旧任务并忽略迟到结果。这是明确的运行边界，不承诺任意长度或任意输入都能处理完。
- Pangu 能处理简单单反引号内容，但不是完整 Markdown 解析器。不保证多反引号、围栏、HTML、代码或结构化文本不变，请自行核对。
- URL 薄层保护大小写混合的 HTTP(S)、Unicode 路径/查询和 IPv6 方括号主机。尖括号形式 `<https://...>` 内的 URL 整体保留，包含裸方括号、花括号和句读。
- 裸 URL 以空白、尖括号、引号、反引号及路径中的 `[]{}` 为边界；IPv6 主机的 `[]` 是例外。完整成对的 ASCII/全角圆括号可以留在路径中；括号外的中英文全角句读结束词元；未闭合或交叉的括号按正文处理。
- 裸 URL 与无分隔的正文有固有歧义。含复杂标点、原始方/花括号、交叉括号或需要精确指定范围的 URL，请用 `<...>` 包裹，或先百分号编码。没有通用 URL/Markdown 解析器。
- URL 使用与输入不冲突的 ASCII 占位符，一次性送入官方 `spaceText`；恢复时核对数量、顺序和唯一性，异常时不发布结果。
- 输入仅在本机处理，不上传、不保存。页面原有站点统计不接收输入文本。

## 自动更新与验收

`.github/workflows/validate-static-tools.yml` 每日检查 npm 最新稳定版本。继续验证 semver、npm 元数据、tarball 完整性、精确发布目标和测试期间 main 未前进；升级任务串行处理各依赖。

Pangu 候选实际写入同一个发布路径后，Chromium、Firefox、WebKit 全部通过真实页面/Worker 契约才可发布。不再手工注入一个 bundle 并只测一个例子。共享契约覆盖：

- 普通间距、真实标点变更、简单 inline code、换行与空白
- scheme 大小写、Unicode/货币/假名/〇等路径、IPv6、圆括号、`[]{}` 后续正文和占位符碰撞
- 大输入、180k 未闭合围栏的可响应与有界完成/超时
- 原文/结果分离、重复处理、复制、清空、取消、迟到结果、超时释放、加载失败与异常

旧 insertion-only 扫描器、只针对其私有语义的 mutation 测试和未使用的 4.0.7 bundle 已删除。仍保留有价值的 URL/输入/大输入测试，转入当前实际处理契约。

历史研究证据保留在 [PR #203](https://github.com/linchun7/linchun7.github.io/pull/203) 及其 Actions 运行中；该研究表明官方 URL 和大输入行为需要真实应用保护，不能仅凭库成熟就免检。
