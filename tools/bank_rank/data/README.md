# 中国银行业100强数据说明

本目录保存 `tools/bank_rank/` 的结构化数据。

## 数据范围

当前数据文件已完成 **2016–2025** 十个榜单年度、共 1000 条记录的结构化回填。2026-08-19 又完成 V4 数据资产复核：对十个年度重新建立“权威来源 → 完整表交叉 → 协会汇总/构成反校验 → 异常项官方取证”的证据链，并将每一年度正式记录的 SHA-256 与审计台账绑定。V4 未发现需要继续修改正式 1000 条记录的新错误。

正式前端范围由 `rankings.json` 控制；历史年度只有在来源、实体映射、排序和摘要校验达到同一标准后才进入清单。

榜单按 **核心一级资本净额** 排序。`rankingYear` 表示榜单的标称年度，并不等同于网页实际发布日期；`publishedAt` 单独记录实际发布日。`dataYear` 是榜单采用的数据对应的年末年度，满足 `dataYear = rankingYear - 1`。例如 2018 年榜单采用 2017 年末数据，并于 2019 年发布；2025 年榜单采用 2024 年末数据。

## 文件结构

- `rankings.json`：正式数据清单、年份元数据、指标口径和年度文件路径。
- `banks.json`：稳定银行实体 ID、规范名、历史名称/别名和银行类型。
- `relations.json`：更名、新设合并等机构沿革事件。
- `years/{year}.json`：对应榜单年度完整100强记录。
- `source-snapshot.json`：来源元数据、记录数、年度正式记录 SHA-256 和规范化说明。
- `audit.json`：逐年复核、实体治理、并列名次、规范化及特殊项审计。
- `verification-v4.json`：V4 内部数据资产审计台账，逐年记录证据等级、权威来源、完整表交叉来源、汇总反校验、异常项、限制、拒绝来源和正式记录 SHA-256。

前端先读取 `rankings.json`，再按清单加载银行实体、关系和年度记录。年度拆分后，新增未来年份不需要扩张一个巨型 JSON。

## V4 证据等级与复核规则

V4 不采用“多个网站都这么写”的多数票逻辑。证据等级如下：

- **A1**：中国银行业协会正式发布页、附件或协会原始榜单图片。用于锁定榜单口径、年度、汇总值、机构构成，以及能够取得的原始榜单。
- **A2**：银行官方经审计年报、官方财务摘要或监管/银行正式披露。用于解决单行财务数值冲突和异常值。
- **B1**：银行官网转载《中国银行业》/协会材料、人民网等权威转载。主要用于旧协会详情页不可稳定回查时确认发布时间、方法和榜单锚点。
- **B2**：可搜索的完整榜单转录。用于100行逐行比对和发现差异，但与 A 类来源冲突时不能作为最终裁决依据。
- **C**：其他二手转录。仅用于发现潜在冲突；已确认错误的来源会进入 `verification-v4.json.rejectedSources`。

每一个榜单年度至少经过以下层级：

1. 校验100条记录、核心一级资本非增序、竞赛排名、稳定实体 ID 和年度 SHA-256。
2. 与至少一份完整可搜索榜单或原始榜单图片做全表逐行比对。
3. 有协会正式汇总值/机构构成的年度，用100条正式记录重新求和或计数反校验。
4. 对字符、小数点、正负号、机构名或跨来源冲突下钻到协会原图/附件，或银行官方年报/财务摘要定值。
5. 更名按同一法律主体连续追踪；合并、吸收合并、新设合并不自动继承前身排名。

这里的“全表逐行比对”是指将100行榜单字段与原始图/附件或独立完整表逐项核对，**不等于**为100家银行每个字段分别查阅各自年报。只有发生冲突或明显异常的单元格才继续下钻到银行官方年报/财务摘要。这样既保证完整表不漏行，又避免夸大证据强度。

2017 年目前仍标记为 `verified_with_legacy_primary_gap`：协会历史归档/发布事实可以确认，但旧详情页或附件仍无法稳定回查，因此继续明确记录缺口，不猜测历史页面 ID。2017 年正式100行仍通过完整表交叉、实体连续性、排序/SHA 及可取得的权威材料验证。

2022 年的协会正式详情页 exact URL 已恢复为 `https://china-cba.net/Index/show/catid/14/id/40979.html`，并由协会历史归档中的同名条目与 《2022年度中国银行业发展报告》官方目录附件（附录2“2022年度中国银行业100强榜单”）形成冗余官方锚点，因此 V4 状态提升为 `verified`。需要注意，部分自动化运行环境当前连接 `china-cba.net:443` 会超时；这是网络可达性限制，不再是历史页面 ID 缺失。

## 银行实体与更名/合并

年度记录通过稳定 `bankId` 连接，不直接依赖银行名称字符串。

纯更名属于同一法律主体，使用同一个 `bankId`，历史名称写入 `aliases`，并在有可靠来源时于 `relations.json` 中记录日期和来源。例如 `南充市商业银行` → `四川天府银行`、`华融湘江银行` → `湖南银行`、`威海市商业银行` → `威海银行`。

合并、吸收合并、新设合并 **不等同于改名**。新主体不会自动继承前身机构的历史排名。海南农村商业银行的新设合并关系即按独立主体处理；历史上的包商银行等机构也不会仅因后续重组而把排名并入新主体。

银行类型按机构法律/业务类型维护，不为了匹配某一年度发布文章中的汇总分组而修改实体类型。2019 年协会正文报告 63 家城商行、19 家农商行，但完整榜单同时包含秦农银行；秦农银行为农村商业银行，因此该年度协会分组数字作为发布口径保留在审计中，不作为实体类型强制校验依据。

## 来源、规范化与拒绝来源

优先使用中国银行业协会正式发布页、附件或原始榜单图片确定榜单口径；历史页面只有图片时，以原始表图逐行转录，并使用协会公布的汇总值反校验。可搜索公开文本页用于辅助结构化和交叉核验；遇到字符、小数点、正负号或机构名异常时，以原始表图、银行官方年报或同等级权威来源为准，并将处理写入 `source-snapshot.json`、`audit.json` 和 V4 验证台账。

2018 年原始榜单图片的 100 条记录逐行汇总后，核心一级资本净额为 124601.69 亿元、资产规模为 1874486.02 亿元、净利润为 16899.57 亿元，与协会公布口径一致。公开文本镜像中的机构名重复、数字漏位和字符识别问题均按原始表图校正。

第三轮复核已确认并修正两处旧仓内数值错误：

- 2016 年天津农村商业银行净利润 `26.00 → 26.35` 亿元，以该行 2015 年官方年报合并口径净利润复核。
- 2021 年中国建设银行资产 `281332.54 → 281322.54` 亿元，以建设银行 2020 年官方财务摘要复核。

V4 再次复核这些修正，并额外确认 2024 年瑞穗银行（中国）资产 `1286.84` 亿元与其 2023 年官方年报一致。V4 没有发现需要继续修改正式记录的新错误。

`verification-v4.json` 还显式保存已知错误来源，例如：2019 年部分完整表存在小数点/OCR 错误；2021 年某转录把建设银行资产写成 `281332.54`、把蒙商银行亏损漏掉负号；2022 年旧转录存在 `5.868.54`、`33186` 等格式问题；2025 年某完整转录存在机构名称系统性错位。此类来源以后仍可用于发现差异，但不得作为冲突值的最终依据。

## 口径与并列排名

2023 年起榜单首次纳入外资法人银行，因此跨 2022/2023 比较需考虑参评范围变化。

榜单允许并列。2024 年瑞穗银行(中国)与花旗银行(中国)核心一级资本净额均为 210.20 亿元，并列第 95 名，下一名为第 97 名。validator 使用竞赛排名规则，不要求名次唯一。

对能从中国银行业协会正式发布材料明确确认机构构成的年度，`officialComposition` 会额外校验上榜银行类型数量。2019 年因协会发布分组与秦农银行法律类型存在上述口径冲突，仅记录 `reportedComposition`，不强制覆盖实体类型。

## 页面展示

页面视觉和信息层级与站内 iCloud / 医院排名工具保持一致：不单独显示黄色数据范围提示，不在表格右侧放逐年协会来源链接。表格下方左侧统一保留一次“数据来源：中国银行业协会”和排名/实体处理说明；年度榜单主表显示当年榜单名称，历史详情再按稳定银行实体聚合。

## 校验与静态渲染

```bash
python tools/bank_rank/scripts/validate_data.py
python tools/bank_rank/scripts/validate_verification.py
python tools/bank_rank/scripts/test_future_year.py
python tools/bank_rank/scripts/render_static.py
python tools/bank_rank/scripts/render_static.py --check
PLAYWRIGHT_BROWSER=chromium node tools/browser-tests/bank-rank-smoke.mjs
```

`validate_data.py` 检查正式清单中的每年100条、榜单/数据年度关系、`scope` 年份范围与历史缺口声明、前端 `bankTypes` 完整性、稳定实体引用、记录原始名称、名称/别名冲突、核心一级资本非增序、竞赛排名、已记录的官方汇总值、可强校验年度的机构构成，以及来源摘要中的年度 SHA-256 和元数据。

`validate_verification.py` 专门校验 V4 证据台账：要求审计年份与正式清单完全一致；逐年重新读取正式 `years/*.json` 计算 SHA-256，并要求与 `verification-v4.json`、`source-snapshot.json` 同时一致；每年必须存在权威来源、完整表交叉来源、汇总/结构反校验说明、异常项/限制数组；拒绝来源必须记录年份、HTTPS 地址和拒绝原因。这样修改任何正式年度数据后，如果没有同步更新审计证据，CI 会直接失败。

`test_future_year.py` 先验证当前生产数据证据台账，再用合成未来年度验证新增年份只需按数据契约更新清单和 scope，无需修改结构 validator；负例会在同步摘要 SHA 后明确验证同一年重复实体仍被拒绝。合成未来年不会被要求伪造一份生产证据台账，因此证据约束与未来扩展性互不干扰。

`render_static.py` 自动选择最大年份生成页面元数据与最新年度完整100强无 JavaScript 静态榜单，并使用 CSS/JS 内容版本避免 CDN 或浏览器继续命中旧资源；`--check` 同时阻止已移除的黄色范围提示和逐年来源链接重新进入静态页。

`bank-rank-smoke.mjs` 接入现有 Playwright Chromium / Firefox / WebKit 矩阵，覆盖默认最新年、历史年份切换、2018 完整恢复、历史名称搜索与实体聚合、筛选、排序、来源/文案约束、缓存版本、控制台错误、完整100条静态 fallback，以及关键历史数据回归。由于 smoke 会执行 `test_future_year.py`，三浏览器 CI 同时会执行 V4 生产证据台账校验。
